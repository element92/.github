# Security Policy

## Reporting a Vulnerability

**Do not open a public GitHub issue for a security vulnerability.** Issues in this organization are visible to anyone with repository access, and a public report can expose a problem before it's fixed.

Instead, report it privately using one of these channels:

1. **Preferred: GitHub Private Vulnerability Reporting.** If enabled on the affected repository, go to the repo's **Security** tab → **Report a vulnerability**. This creates a private draft security advisory visible only to repository maintainers, with a built-in space to discuss and coordinate a fix before anything is disclosed.
2. **Email:** security@lydium.ca <!-- update this if a different address should be used -->

Please include:
- A description of the vulnerability and its potential impact
- Steps to reproduce it, or a proof of concept
- Any affected repository, file, or component you're aware of

## Scope

This applies to all repositories owned by the Lydium GitHub organization, including internal tooling, client deliverable templates, and infrastructure/automation scripts. If you're unsure whether something qualifies as a security issue versus a regular bug, err on the side of reporting it privately — it's easy to downgrade a private report to a public issue later, but not the reverse.

## Response

We aim to acknowledge reports within a few business days. As a small team, response time may vary — if a vulnerability appears actively exploited or poses an urgent risk, note that explicitly in your report.
